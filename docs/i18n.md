# Internationalization (i18n) — Foundation

Status: **foundation only.** Arabic is **not** publicly reachable — the EN/AR
switcher stays hidden behind `ARABIC_ENABLED = false` in `src/components/layout/Header.tsx`,
and the `/ar` subtree is `noindex`. The Arabic dictionaries are **machine-draft
pending review**.

## Routing model — decision: `/ar` route-prefix (Option A)

English lives at the site root (`/…`); Arabic lives under `/ar/…` as explicit
routes. This was chosen over the canonical `app/[locale]/` restructure because it
is additive and low-risk for a hidden foundation phase — it leaves every English
page and link untouched.

**Trade-off — `<html>` attributes.** With this model the root `<html lang="en"
dir="ltr">` (rendered by the root layout) can't be changed per-route on the server.
`src/app/ar/layout.tsx` therefore renders an inner `<div dir="rtl" lang="ar">` and a
small client helper (`components/i18n/LocaleHtmlAttrs`) that sets
`document.documentElement.dir/lang` at runtime for CSS logical properties and
assistive tech. There is a brief LTR flash before hydration on `/ar` — harmless
while the subtree is hidden and `noindex`.

### Deferred: `app/[locale]` migration (documented future step)

When Arabic goes public, migrate to `app/[locale]/…` with middleware so `<html
lang/dir>` is correct at SSR (removing `LocaleHtmlAttrs`) and one page tree serves
both locales. This is a separate, larger refactor — **not** part of the foundation.

## Font — decision: IBM Plex Sans Arabic

Loaded via `next/font/google` in `src/app/ar/layout.tsx`, exposed as
`--font-arabic`, and mapped to the Tailwind `font-arabic` family — scoped to the
`/ar` subtree only. English keeps **Poppins**. IBM Plex Sans Arabic pairs cleanly
with Poppins' geometry and covers the needed weights (400/500/600/700).

## Dictionaries & parity

- English copy: `src/content/en/*`. Arabic mirror: `src/content/ar/*`.
- Each Arabic dictionary is typed against its English source via
  `Translatable<typeof enDict>` (see `src/lib/i18n.ts`) — or the shared interface
  where one exists (`SystemEnhancedData` for the façade page). A missing, renamed,
  or extra key is a **compile error**, so translations can't silently drift.
- `src/content/dictionaries.ts` exposes `getDictionary(locale)` as the single
  access point.
- **Every machine-draft file carries a `⚠️ MACHINE DRAFT` header** and must keep it
  until the owner reviews and corrects GFRC/GRC terminology.

## RTL conventions

- Direction is set by `ArLayout` (`dir="rtl"`). Under a `dir="rtl"` ancestor,
  Tailwind `rtl:` variants and logical utilities apply automatically.
- **Prefer logical spacing** (`ps-`/`pe-`, `ms-`/`me-`, `start-`/`end-`) over
  physical (`pl-`/`pr-`, `ml-`/`mr-`, `left-`/`right-`) so components mirror with no
  per-locale code. `flex-row` reverses automatically under RTL.
- Use `rtl:` variants only for cases logical properties can't express (e.g. mirroring
  an arrow icon: `rtl:-scale-x-100`).

## Reference implementation

`/ar/systems/gfrc-grc-facade-cladding` renders the **same** shared component as the
English page (`SystemEnhancedLayout`, with the shared
`components/systems/facade-cladding-visuals`), driven by `getDictionary('ar')`. It
proves the routing + font + RTL + dictionary pipeline end-to-end. (The prior
divergent `/ar/systems/facade-cladding` stub, which used a separate `FacadeContent`
layout, was retired so both locales share one component and one dictionary shape.)

## Preview-only toggle (owner review)

The EN/AR switcher is shown in **non-production only** (`VERCEL_ENV !== "production"`,
i.e. Vercel previews + local dev) so the owner can review the Arabic experience without
exposing it publicly. The root layout reads `VERCEL_ENV` on the server and passes
`previewMode` to `Header`; visibility is `previewMode || ARABIC_ENABLED`. In preview a
`معاينة — قيد المراجعة` ("Preview — under review") badge sits next to the toggle so
screenshots are never mistaken for launched Arabic. The `/ar` subtree stays `noindex`.

The toggle never 404s: it links to `/ar<path>` only for routes in `TRANSLATED_AR_ROUTES`
(`Header.tsx`), and otherwise falls back to `/ar` (the Arabic preview landing,
`src/app/ar/page.tsx`). Keep that set and the landing's list in sync as pages are translated.

### 🔓 Launch switch (one line)

When Arabic is ready for production, set **`ARABIC_ENABLED = true`** in
`src/components/layout/Header.tsx`. That makes the toggle visible in production too
(`previewMode || ARABIC_ENABLED`). Also remove `noindex` from `src/app/ar/layout.tsx` and
complete the SEO/translation steps below.

## Review checkpoint & path to public

1. **Owner reviews `src/content/ar/*`** and corrects GFRC/GRC terminology. Remove the
   `⚠️ MACHINE DRAFT` headers as each file is approved.
2. Translate the remaining core-journey pages (home, systems, packages, contact,
   RFQ + engineer-guidance forms) and translate the SVG diagram annotation labels.
3. Add `hreflang` alternates + per-locale metadata (SEO), and capture locale on leads.
4. Remove `noindex` from the `/ar` layout and flip `ARABIC_ENABLED = true`.
5. (Optional but recommended) perform the `app/[locale]` migration for correct SSR
   `<html>` attributes.

Steps 2–5 are **out of scope** for the foundation and gated on step 1.

## How to translate another page

1. Move the page's English copy into `src/content/en/<area>.ts` (if still inline).
2. Add `src/content/ar/<area>.ts` typed `Translatable<typeof enDict>`, machine-draft,
   with the `⚠️ MACHINE DRAFT` header.
3. Register both in `src/content/dictionaries.ts`.
4. Create the `/ar/<route>` page rendering the shared component with
   `getDictionary('ar')`. Use logical spacing / `rtl:` where directional.
